# Doodle Jump for Wii

An endless vertical jumper for the Nintendo Wii, written from scratch in C on
libogc/GX and tested in Dolphin. It follows the *mechanics* of the phone game
Doodle Jump (auto-bounce, wrap-around screen edges, springs, jetpacks,
monsters) but **none of its assets**: every shape is drawn with anti-aliased
line/curve primitives at runtime and all music and sound effects are
synthesised at boot. There is no art, audio or code from the Android APK in
this project.

## Controls

| Action | Wii Remote |
| --- | --- |
| Move left / right | Nunchuk stick, tilt the remote, or d-pad |
| Shoot up | A or 2 |
| Start / resume / restart | A, 2 or + |
| Pause | + or − |
| Back to title | B or 1 |

The game is always in auto-bounce: you never press jump, you steer.

## Build

Requirements: devkitPro with devkitPPC (`C:\devkitPro` by default).

```powershell
cd doodle-wii
.\build.ps1                       # release build, title screen + normal play
.\build.ps1 -Extra AUTOPLAY=1     # scripted player for automated runs
.\build.ps1 -Clean                # rebuild after changing flags
.\build.ps1 -Extra PERF=1         # on-screen frame time / fps
.\build.ps1 -Extra TELEMETRY=1    # machine-readable telemetry strip
```

`build.ps1` maps the project to a spare drive letter first, because devkitPro's
make does not cope with spaces in the path. On Linux/macOS use plain `make`
with the same variables (`make AUTOPLAY=1`).

The result is `doodle-wii.dol` (load it with wiiload, an SD card, or Dolphin).
Copy `meta.xml` next to the `.dol` for the Homebrew Channel.

`make` does not track CFLAGS, so after changing any flag run `build.ps1 -Clean`.

## Build flags

| Flag | Effect |
| --- | --- |
| `AUTOPLAY=1` | Scripted player: starts and restarts by itself and steers/shoots. Used for unattended Dolphin runs. |
| `TELEMETRY=1` | Draws a black/white cell strip with 38 numeric channels (state, score, timings, pixel counts, autopilot diagnostics). `tools/decode_telemetry.py` reads it back from a screenshot. |
| `PERF=1` | Small text overlay with CPU ms and fps. |
| `CALIBRATE=1` | Ruler/edge calibration pattern instead of the game. |
| `DEBUG_LOG=1` | Gameplay state printed to the Dolphin log every 60 frames. |
| `NOCLEAR=1` | Skips the framebuffer clear (renderer profiling only). |

## Testing in Dolphin

```powershell
.\tools\capture_dolphin.ps1 -Dol doodle-wii.dol -Seconds 10 -Count 4 -Interval 1
python .\tools\decode_telemetry.py shot-01.png     # numbers from a TELEMETRY build
python .\tools\measure_png.py shot-01.png 96 44    # ASCII picture
python .\tools\ink_png.py shot-01.png 106 44       # ink-only view, good for text
python .\tools\zoom_png.py shot-01.png 500 230 120 40   # 1:1 crop
```

The capture uses the desktop compositor (Dolphin's D3D surface cannot be read
with PrintWindow). Dolphin renders the 640x480 image into a shortened surface
(640x395 at the default window size), so all three tools normalise the capture
back to the 640x480 game grid before measuring.

## Layout

| File | Purpose |
| --- | --- |
| `source/main.c` | Boot, 60 Hz loop with measured dt, telemetry packing |
| `source/game.c` | Gameplay, platform generation, camera, HUD, overlays, autopilot |
| `source/gfx.c` | Software RGBA8 rasteriser + GX present, swizzle, dim pass |
| `source/sfx.c` | ASND chiptune synth engine, original loop and effects |
| `source/input.c` | WPAD wrapper (nunchuk / tilt / d-pad) |
| `source/dbg.c` | Telemetry strip encoder |
| `source/font_data.h` | Handwritten font atlas (generated by `tools/make_font.py`) |

See `PORT_NOTES.md` for how the port works and what it deliberately does not do.
